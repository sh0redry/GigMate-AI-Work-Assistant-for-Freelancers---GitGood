# Desktop automatic-start installation

[Chinese guide](../zh/desktop-installation.md). This is a local Electron client with a Docker-managed FastAPI backend, separate worker, PostgreSQL and pinned WAHA. It is not a hosted service, an offline mode, or an App Store release. Internet is required for first-time runtime downloads, WhatsApp and AI calls.

## Install and start

1. Download the installer matching your device from the repository's GitHub Releases: Windows x64 `.exe`, Mac Apple Silicon `mac-arm64.dmg`/`.zip`, or Intel Mac `mac-x64.dmg`/`.zip`. For a zip, extract the `.app`; for a DMG, copy the app to Applications before running it.
2. On first start, set your own account and a password of at least 12 characters. There are no bundled demo accounts, customer messages, API keys or WhatsApp sessions.
3. First setup creates an independent, empty profile. **Installation, normal startup, upgrade and reinstall do not delete existing databases, credentials, chats or WhatsApp sessions.** The Windows uninstaller retains app data. Build IDs are provenance only, and old reinstall-reset markers are ignored. Source repositories and existing developer data are not imported.
4. Docker Desktop is required. The app detects the local CLI and daemon, opens an existing Docker Desktop, and waits for it. If absent, use the official Docker download button; finish Docker's installer, license, permissions and any required Windows WSL2/reboot once. GigMate cannot accept OS security prompts on your behalf. Python and Node.js do not need to be installed on the user's computer.
5. Optionally enter your DeepSeek key, explicitly enable AI and enter reviewed **USD per 1,000 input/output tokens** and a per-request USD budget (greater than zero, maximum 10). These are not CNY per million-token prices. Missing/invalid pricing or credentials keeps AI disabled while the manual workbench starts; the backend cost gate is retained. The key is encrypted through the OS secret store and copied into a separate model-secret volume for API/worker only. The monitor receives only WAHA configuration/bindings and cannot read the model volume. Neither the business renderer nor installer receives the key.
6. Click the start button. The app creates the Python environment inside Docker, migrates a fresh PostgreSQL database, creates the local account/connector with an empty allowlist, then starts WAHA, backend, worker and connection monitoring. After health checks it opens the normal workbench. Sign in with your chosen account, scan WhatsApp and authorize individual chats/sending separately.

Later launches automatically reuse the encrypted profile and its existing Docker project. Normal quit stops that stack and preserves volumes. In **Startup/connection settings**, a blank key preserves the saved credential; untick AI and save/start to disable it, or select explicit key deletion. Old profiles without accepted pricing start with AI off. An occupied saved loopback port falls back to a free port, persists it and updates backend trusted origins before opening the workbench. The desktop browser partition is independent of developer browser sessions. Only local Unix sockets/Windows named pipes are allowed.

If the profile is corrupt or the OS keychain cannot decrypt it, startup stops **without deleting or recreating anything**. Preserve the app profile, OS keychain and Docker volumes and contact the maintainer. Reinstall is not a recovery/backup mechanism; OS-protected credentials are not automatically portable to another machine. There is no automatic backup/export feature in this batch.

## Optional old-environment cleanup

Cleanup is separate from startup. Open the setup screen's **Old environment cleanup** section and request a resource list. The current workbench is excluded. By default only obsolete desktop resources with the desktop ownership label and valid project label are listed. Separately opt in to list legacy `gigmate-waha-a02`, `gigmate-waha-team` and `gigmate-waha-recovery` resources; these may contain backups. Unlabelled, similarly named resources are not deletion targets.

Review each container/volume name, ID, project and creation time, select exact resources and type the displayed deletion phrase. The single-use review expires after two minutes. Docker locality and every selected identity are rechecked before deletion; a changed identity or selection outside the reviewed list refuses the operation. No prune, wildcard deletion, profile deletion or directory scanning occurs. Deletion is permanent and can partially complete if Docker fails; refresh the list after an uncertain result, never automatically retry. Back up anything needed yourself before opting in.

## Manual correction when AI missed information

Open the work order and choose **Add or correct fields**. Choose address, schedule, summary, quantity, specification or deadline, enter the correct value, select the actual customer message and review the change. Only tick customer confirmation when the original message explicitly supports that fact. Otherwise the value stays proposed. Save is an explicit merchant decision, never an AI-confirmed write. Schedule changes update the calendar in the same transaction; unsent old drafts are invalidated and any still-needed question uses the new field values. Rejected drafts do not block this operation. Stale/revoked/foreign sources, closed orders and schedule conflicts are refused; unknown save results retain the original request for explicit recovery. No message is sent by editing a field.

## Distribution limits

The release workflow resolves the tag to one fixed commit, validates backend/contracts against PostgreSQL, and builds all three native targets with read-only repository access. Only a separate publishing job has contents-write permission. It generates and verifies `SHA256SUMS.txt` over the actual installers and `SOURCE_COMMIT.txt` before uploading to an existing draft release; it refuses a moved tag and does not overwrite existing assets. Checksums are integrity evidence, not code signing or an attestation. Updating a PR does not rebuild or replace already-uploaded installers: native release generation and launch acceptance still need a new tag/run.

Desktop CSP allows the controlled blob audio/PDF-frame preview paths while retaining script/object/remote-origin restrictions and the existing iframe sandbox. `python scripts/check_desktop_preview.py --browser <Chromium-or-Edge>` checks real browser WAV metadata, sandboxed blob navigation and CSP violations with synthetic local content. It does not prove the OS/native PDF viewer, authenticated real attachment display or phone delivery; check those on each target platform.

This initial GitHub distribution has no Apple Developer ID/notarization or Windows Authenticode certificate. macOS or SmartScreen can show an unidentified-developer warning; install only the team's release you intended to use and follow the OS's explicit approval flow. Auto-update is not enabled. Windows ARM, Linux installers, offline dependency installation, Docker redistribution and uninterrupted background operation after quitting are not delivered. Native build/launch and real phone/AI delivery acceptance are separate evidence; consult the release notes for exactly which checks completed.

Docker official setup: [Mac](https://docs.docker.com/desktop/setup/install/mac-install/), [Windows](https://docs.docker.com/desktop/setup/install/windows-install/). Docker's licensing and OS requirements apply independently.
