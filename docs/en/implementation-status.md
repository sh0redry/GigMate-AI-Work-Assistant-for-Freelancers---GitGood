## Real-model acceptance gates and reviewed-media promotion (roles B/C) — 2026-10-17

Second 2026-10-17 batch, covering rows 3 and 4 of the milestone table. The supplier-quality part still needs an operator's own key; everything that can be enforced locally is enforced and tested.

**Text model (row 3)**

- **Budget:** new `gigmate/extraction/budget.py` sums today's committed `model_call_traces` for the account and attaches the counters to `ExtractionRequest`. `GIGMATE_LLM_DAILY_CALL_BUDGET` / `GIGMATE_LLM_DAILY_TOKEN_BUDGET` set the bound; with no bound, live traffic refuses with `llm:budget-not-configured`, at the bound with `llm:budget-exhausted`. Both happen before client construction and persist zero usage. Counting trace rows (not a separate counter) keeps usage and evidence in agreement; a vendor that omits token counts still consumes one call.
- **Per-account authorization:** `GIGMATE_LLM_LIVE_ACCOUNTS`, when set, narrows live traffic; others get `llm:account-not-authorized`.
- **Time basis:** the worker attaches the inbox received time (UTC `Z`) and `GIGMATE_WORKSPACE_TIMEZONE`. Missing either refuses with `llm:time-basis-missing`. Prompt v1.1.0 resolves relatives against that basis only and requires `Z` timestamps, which the contract also enforces (`llm:response-schema-failed` on offset/date-only).
- **Provenance re-binding:** `_bind_provenance` overwrites `conversation_id`, `base_context_version`, `work_order_id`, `base_work_order_version` and every change's `sources` from the request before validation; a response naming an order outside the candidate set or a different base version becomes `llm:provenance-mismatch` with no changes. After the call, the worker re-reads the conversation and records `SOURCE_SUPERSEDED` instead of materializing a change if the context advanced in flight.
- **Timeout/unknown:** only connect failures, 408 and 429 are retried. Read timeouts, dropped connections, 5xx and malformed 2xx bodies become `llm:result-unknown` / `llm:response-malformed`, persist `total_tokens = NULL`, set `EXTRACTION_RESULT_UNKNOWN` on the job and are never resubmitted. HTTP reasons are stable classes plus status (`_sanitised_http_reason`); URLs, headers, exception text and keys are not persisted.
- **Default off:** live still needs `GIGMATE_LLM_LIVE=1` + `GIGMATE_LLM_ALLOW_LIVE_ORIGIN=1` + key + JSON-capable model, and now also a time basis and a budget.

- **Vendor-correct endpoints:** `LLMProvider._resolve_endpoint()` (new) returns `GIGMATE_LLM_ENDPOINT` when set, otherwise the vendor's documented base URL — `deepseek` -> `https://api.deepseek.com`, `openai` -> `https://api.openai.com`. `custom` has no default and is refused with `llm:not-configured`. Auth and bad-request responses fail on the first response. HTTP failure messages are sanitised (`_sanitised_http_reason`) so traces keep the failure class without endpoint or credential detail.
- **Token accounting:** the vendor `usage` object is normalised to `prompt_tokens` / `completion_tokens` / `total_tokens` (vendor-specific extras such as DeepSeek's cache counters are dropped), carried on `ExtractionOutcome.usage`, and persisted through `persist_proposal` into three new nullable columns on `model_call_traces` (migration `0014_llm_usage`). - **Configuration validation:** `gigmate.env_check` now validates the model configuration in strict mode, but only when its gate is on — `GIGMATE_LLM_LIVE=1` requires a known vendor, a model and a non-placeholder key, `custom` requires `GIGMATE_LLM_ENDPOINT`, and any endpoint must be `https`. `GIGMATE_MEDIA_*` is validated the same way, including that DeepSeek is not a legal ASR vendor. - **Dependencies:** `httpx` is now declared explicitly in `apps/backend/pyproject.toml`; it was imported by both vendor adapters while only present as a transitive dependency.
- **Tests:** new cases in `tests/test_extraction.py` for per-vendor endpoint resolution, `custom` without an endpoint, `deepseek-reasoner` refusal, no-retry on 401, retry on 429, token-usage capture, `usage is None` on refusal, and `test_persisted_trace_records_token_usage_only_for_billed_calls`; new strict-mode cases in `tests/test_env_check.py`. `tests/test_waha_migration.py` pins the new Alembic head `0014_llm_usage` and asserts the usage columns exist after `upgrade head`.

## Role B independent-review fixes — 2026-10-10

Applied on PR head `e44d8ec` (branch `WillW27/role-b-deepseek-integration` on GitHub) in response to the independent review of the same commit. The reviewer distinguished between intentional design (kept as-is), reproducible defects (fixed in this PR), and pre-activation acceptance gates (recorded in the role-b-extraction docs, not in scope here). Reproducible defects (P2) fixed:

- **Smoke-script exit code.** `scripts/smoke_deepseek.py` previously returned 0 for every `needs_review` outcome unless `notes == ("llm:not-configured",)`. Configuration / transport / parse / schema / lock failures (`llm:seam-pending`, `llm:http-failed`, `llm:response-malformed`, `llm:response-schema-failed`, `llm:prompt-load-failed`) all silently produced a green exit. The script now classifies via a `_classify_exit_code` helper: matched → 0; LLM-driven `llm:needs-review` → 0; any infrastructure-failure note → 1; any other `needs_review` note → 1 (conservative). Re-verified: with the skeleton lock on and the live gate open the script exits 1; with the live gate closed the script exits 2 (env check) before reaching the model.
- **Registry metadata JSON serialisation.** `gigmate.extraction.registry.list_provider_metadata()` previously read `cls.prompt_version`. After the prompt-version was made an instance-level `@property` on `DeterministicProvider` (so deterministic and LLM providers stay in lock-step with the prompt file), reading the property off the class returned the `property` object and `json.dumps(...)` raised `TypeError: Object of type property is not JSON serializable`. The helper now constructs each provider once and reads `instance.prompt_version`; if construction fails (e.g. a future provider needs runtime config) it falls back to the class attribute. Round-trip is verified by a new regression test.

Regression tests added (synthetic, no network):

- `test_list_provider_metadata_is_json_serialisable` — asserts the helper returns plain strings and round-trips through `json.dumps` for all three registered providers.
- `test_smoke_classify_exit_code_marks_infra_failures_as_nonzero` — loads `scripts/smoke_deepseek.py` via `importlib`, calls `_classify_exit_code` with each documented notes tuple, and asserts exit codes.
