## Delivered behavior

- One product frontend: no environment picker, injected backend destinations, public credential hint, fictional input action or fallback service. A single loopback development target and same-origin delivery API preserve session/CSRF. Retired environment URLs stop without login/API reads; legacy unknown approval journals are preserved and block new writes rather than migrate automatically. Developer synthetic resources/tests remain outside the product flow.
- New-order workflow: owned/allowlisted conversations, summary, missing/date-only/timed choices, Hong Kong time, address and separate incoming-current-source selection. Existing open orders require explicit additional-order consent. Exact review changes invalidate consent. #26 target commands are prepared but gated off by the server; no unsupported route is probed or fabricated write reported.
- Lifecycle review: legal status transitions, terminal-state explanation, exact order version and explicit effects. #27 saving remains disabled. Address/key-item, assignment/deferred follow-up and task mutation dependencies are labelled unavailable. No new backend creation/status rules or workaround for the known #26 bugs.
- Original numbered order commands: journal before POST, account/API scope, immutable original content/version/key, frozen confirmation display metadata, no resend on reads/remount/logout, explicit reviewed recovery only. Getter/read/write/cleanup denial and another mount's newer journal block unsafe writes; responses are checked for ownership/version before cleanup. Original authentication uncertainty remains unresolved, never inferred as unsubmitted.
- Separate internal month/agenda/task workspace, closed-order history, cross-midnight/day-only display, keyboard arrows/Home/End, date selection and direct order navigation. Download requests abort on navigation/logout so late account data is not saved into a later screen.
- `GET /calendar-events/{id}.ics`: authenticated/owned, read-only, current order/schedule version, active formal timed appointment only; stable UID, order-version sequence, UTC instants, original timezone note, confirmed location, UTF-8 folding, escaping, no-store/private download. No migration/table change or external calendar write. Based on [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html). Reimport/update is manual; no automatic sync or duplicate-free client import promise.
- Owned/allowlisted conversation list and safe review queue metadata, historical-round labels, current original text, linked orders, missing-item explanation and attachment/source-review navigation. No raw provider payloads or new model invocation. Read-side full-history scans remain a nonblocking scale concern; #28 is not claimed complete.
- Capability status/help, accurate approval-versus-send wording and open-items reason descriptions. A manual sender remains available under its own authorization; no C/A execution link is fabricated. Real models/automatic creation/OCR/ASR and free-generation automatic replies remain disabled dependencies.
- Responsive layout, one main landmark, skip link, focus after navigation, keyboard/month controls and 44px standard controls. Web manifest/icon and standalone start metadata without service workers/private offline caches. Supported browsers may install over HTTPS/loopback; native installers/signing are not delivered. [MDN install requirements](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).
- Container compilation uses `bundle` after formatting; full tests run before release with pinned Python, avoiding a missing test-interpreter failure in the Node-only web image.
