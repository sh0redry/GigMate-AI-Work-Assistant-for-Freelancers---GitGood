## Implemented boundary

A logged-in **业务工作台** now offers order search/status filtering, details with field states and exact source revisions, all linked conversations, proposal history, explicit internal schedule confirmation, account calendar and selected-order tasks/history. **工单回放** retains the existing fictional inputs in a separately labeled mode. Search/filtering never silently changes the selected order; a hidden selection remains labeled. Unknown values remain missing. Customer proposals, customer confirmations and merchant confirmation are displayed separately.

Every linked conversation and message page is loaded through canonical owned APIs. A missing/denied conversation fails the read rather than exposing a partially writable snapshot. Because ChangeView has no conversation ID, confirmation derives its context from exact, unrevoked source revisions belonging to one linked conversation. Missing or mixed provenance is blocked. Review freezes proposal content, source/context and order version; refreshing changed data invalidates that review. An explicit checkbox is required before dispatch. Only schedule confirmation implemented on main is enabled; terminal orders, conflicts, invalidated proposals, stale reads and unsupported fields are blocked. Backend validation remains final authority.

The calendar marks current/other orders, tentative/formal entries, work-order versions and buffer minutes. Date filtering uses Hong Kong day boundaries for timed events, including overnight overlap, while all-day dates retain their original zone/date. Conflict IDs resolve calendar entries before order titles. Tasks distinguish pending/blocked/completed/cancelled, deadlines, dependencies and source revisions; the default hides history and the all-history filter retains cancelled preparation tasks.

No backend, migration, contract model, generated schema/type or connector change. ## Reviewer reproduction

Use a **fresh disposable seeded replay environment**, API and deterministic worker following [getting started](getting-started.md), then `npm ci` / `npm run dev` in `apps/web`. Do not seed/reset a real WAHA installation. Choose the configured development password, log in and select **业务工作台** to inspect initial v3/missing address. Switch to **工单回放**, submit 15:00 conflict, wait for the worker, verify no confirmation; submit 16:30, wait, open **核对并确认安排**, compare old/new/source versions, tick consent and confirm. Return to business: verify v4, current/other calendar labels, new preparation task and cancelled history. Reload and sign in, filter status/search and follow sources; use `other` to check account isolation. Repeating a fixture on an existing database does not reset its state.

Review all linked conversations with the automated multi-conversation fixture; the seeded manual scenario has one conversation per order. Multiple HTTP reads do not form an atomic database snapshot; server version/context checks prevent accepting stale confirmation. Long queue/failure monitoring and arbitrary message edits/revocations remain future UI scope. Independent E/team review is still required before merge.
