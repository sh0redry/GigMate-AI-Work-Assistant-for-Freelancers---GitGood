# 验收标准与证据要求

## 第一阶段 文档与契约

本次验收检查文档基线，业务场景仍是待实现的标准。

- [ ] 英文 README 准确介绍定位、当前状态与英文文档，未引用中文入口。
- [ ] 中英文说明一致，架构、状态、字段和接口有唯一来源。
- [ ] 技术选型、契约来源转换及审批执行有已接受 ADR。
- [ ] 共同样例具有事件、提议、工单、审批和预期行为。
- [ ] 正例通过 schema；反例被拒绝；本地链接及 schema 引用无断链。
- [ ] 验收场景至少覆盖改期、含糊回复、同客多单、重复、撤回、旧审批、未知结果、白名单、隔离和指令注入。
- [ ] 单人自查和后续独立审核规则明确，任务/PR 模板可用。

运行 `python scripts/check_baseline.py` 获取结构检查结果。通过表示文档和样例一致，不表示业务实现正确。

## 第二阶段 可运行骨架

真实命令、迁移、配置与 CI 在实现后检查：clean checkout 启动 replay；事件和提议进入工作台；商户确认后落库；重启保留状态；基本鉴权隔离有效；重复事件不产生重复记录。此时允许固定 AI 桩，但必须标明。

## 完整 P0 的行为验收

共同用例及预期见[场景清单](../../contracts/examples/scenarios.json)。每条必须在实现时记录环境、版本、输入、操作、实际结果和证据路径。

| case_id | 场景 | 必须验证 |
| --- | --- | --- |
| AC-001 | 改期且缺地址/冲突 | 旧正式安排保留，新提议与冲突可见 |
| AC-002 | 含糊“可以” | 不补齐地址或同时确认所有字段 |
| AC-003 | 同客多单 | 无明确依据进入人工归类 |
| AC-004 | 重复事件 | 不重复建单或生成待执行行动 |
| AC-005 | 来源编辑或撤回 | 字段待复核，相关旧审批失效 |
| AC-006 | 批准后新消息/编辑正文 | worker 拒绝过期版本 |
| AC-007 | 发送结果未知 | 不自动重发，保留核对入口 |
| AC-008 | 非白名单或撤销 | 未授权内容不入业务库/模型，撤销阻止发送 |
| AC-009 | 跨账号查询及写入 | 拒绝且不泄露资源存在性 |
| AC-010 | 原文指令注入 | 不改变权限，不访问其他顾客资料 |
| AC-011 | API echo | 不循环回复，已 dispatch 行动不被追溯取消 |
| AC-012 | 本地接收与执行并发 | 已接受的新上下文能阻止旧审批发送 |

## 接入与模型评测

真实接入至少以50条消息及重复/乱序输入核对双方消息 ID、时延、断线与发送状态。记录固定版本和引擎能力，不泛化为 SLA；回放记录不能冒充真实接入。

模型评测后续建立30至50条开发案例和至少20条独立保留测试案例，两人标注并记录分歧。目标为关键字段/状态准确率和冲突/未决问题召回率至少90%；权限用例零次未授权外发/正式改期。目标不等于已达成结果；报告样本数、失败案例和分类结果。

用户研究与任务时间改善另行测量，虚构样例只用于开发。禁止通过只演示成功案例推断准确率或长期效果。
