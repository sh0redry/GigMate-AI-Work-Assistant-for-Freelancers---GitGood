# 有来源约束的 AI 补问

现有审核式文字分析调用可以同时返回补问判断：日期、开始时间、结束时间、
时长和地址分别属于已知、缺失、有歧义或客人明确表示稍后提供。AI 参与语义判断，
没有为每个字段增加一次付费调用。

独立的 1.0.0 补问结构由 `scripts/export_contracts.py` 生成至
`contracts/ai/clarification-assessment.schema.json`。`0024_context_clarification` 迁移为 `proposals`
增加可空 JSON 列，保存判断及服务端捕获的工单依据；旧记录继续可用。
`TimedSchedule` 仍要求开始和结束时间，不完整时间不能借此写入日历。

每个非缺失断言都需要当前已授权客人消息的 ID、修订号和逐字证据。AI 选择真正
未解决的问题、顺序及简洁／友好语气；服务端验证问题集合并把引用事实填入受限
表达，避免回复自由增加事实或执行承诺。原有面向商户的 `draft_text` 摘要不混用。

只有已匹配工单，或商户明确采用并建单的建议，才能使用相应判断。完整／人工
录入事实优先；不完整改期可以单独追问时长，但不覆盖原已确认预约。回复仍是
绑定版本的待审核动作，发送继续需要原有授权与最终发送命令。识别到“稍后提供”
会抑制立即追问；AI 不直接办理正式延期或创建跟进任务。

近期聊天窗口仍有边界。最多三个明确关联的工单可以另外提供共计最多 5000 字节
的先前判断和原文证据片段，读取前重新核对归属、授权和当前消息修订。模型只能
在对应的已有工单上引用，不能套用到新业务或其他工单。新客人消息要求重新分析；
本系统发送回声可以保留事实依据，不递归调用模型。

判断缺失、无效、过时或归属不明时，回落原有模板／人工复核行为，不自动发送，
不盲重试结果未知的付费调用，不确认预约。原文证据只能证明来源，不能证明模型
理解一定正确，因此仍须人工审核，且不能把模拟测试通过宣称为准确率提升。
密钥和连接器凭据不会进入模型上下文。

回归位于 `apps/backend/tests/test_clarification.py`；PostgreSQL、迁移保留数据及
限额虚构需求的供应商验收结果会如实记录在进度文档。

主线新增会话授权边界：只有在最近一次授权变更之后持久接收的来源，才能进入新增的
近期上下文和补问记忆。撤销后重新授权不会自动重新开放旧消息。迁移保守地把已有
会话边界设为当前上下文版本，保留消息与工单，并要求新接收的输入才使用此功能。

此迁移从主线 `0023_agent_drafts` 出发，独立于私有决赛迁移链。不得修改服务器已应用
的决赛迁移，或直接对演示库执行本主线迁移；迁移历史需要另行核对后合流。
主线不需要活动表、口令加入、固定场景或重置钩子。
