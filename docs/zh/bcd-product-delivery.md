# BCD 初阶文字产品交付 — 2026-10-17

本候选接在 main `14aa34e`（PR31／32／33 已合并）之后。它是一版可审查的**文字业务流程**，不代表真实部署、付费模型和手机现场验收都已通过。原方案的媒体和自由 Agent 扩展仍明确列为后续。[English](../en/bcd-product-delivery.md)。

## 商户可以做什么

连接并授权工作对话；引用客户原文手动建单；核对变更；给含糊消息选工单或忽略；记录时间／地址稍后确认；管理资料、承诺和问题；设置工作日、休息、预约间隔和提前准备；批准回复，再明确提交准确正文到既有发送网关；核对本账号回执；处理待办和交付检查；完成／取消／归档；查看内部日历并导出当前有效的已确认预约 `.ics`。

**AI 辅助建单不等于 AI 自动建单。** 只有已有一份归属、原文和版本有效的建议，页面才会显示。选择建议只预填摘要；商户仍要核对原文、明确填写关键值、确认创建。同一收到消息只能通过建议消费一次；断网重试保留原编号。模型本身不会创建正式工单，也不会确认业务字段。

快捷查询只支持“今天／明天安排、哪些等客户、哪些待决定”四类问题，支持中／英／粤写法。答案来自本账号现有记录，并可打开工单；不认识的问题不猜。这是有明确范围的查询助手，不冒充自由问答模型。

完成／取消待办时，核对账号、开放工单、工单版本、待办原状态、仍获授权的当前原文和前置事项。关联需求、待办、工单版本、审计与回执一起保存。完成待办不代表客户同意了时间／地址。服务器明确拒绝第一次检查清单／依赖操作时可重新核对修改；结果未知则保留原操作，不换编号碰运气。

业务发送页面通过服务端提供的 `WahaChoice.conversation_id` 找到准确聊天编号，不再把“会话编号”和“聊天编号”混用。最终仍由后端核对账号、授权、正文、修订与版本。批准、排队、派发、服务接受、送达、已读、未知分别显示。

## 可选的文字模型入口（B）

原来的 `deterministic`、`disabled` 和始终关闭的旧 `llm` 保持兼容。新增 **`reviewed_llm`** 必须由维护者明确配置，默认不启用。配置只留在后端私有环境：

- 选择 `GIGMATE_EXTRACTION_PROVIDER=reviewed_llm`；供应商、模型、地址、密钥见 [B 文档](role-b-extraction.md)。
- 同时明确设置 `GIGMATE_LLM_LIVE=1` 和 `GIGMATE_LLM_ALLOW_LIVE_ORIGIN=1`。
- 设置有效的 `GIGMATE_WORKSPACE_TIMEZONE`；亲自核对供应商输入／输出每千 token 单价，明确填入两个单价，设置有限预算和 token 上限。只靠旧价格表不能启用；估算不是供应商账单的绝对保证。
- Compose 使用原部署命令，在基础文件和既有 WAHA 叠加文件后增加 `-f infra/compose.text.yaml`，沿用同一个私有 `--env-file`。它把配置交给 API／worker，不交给前端。按正常升级流程重建服务，不清空数据卷。示例开关仍关闭。

启动时先检查 provider 名称，再启动心跳／处理循环。未知名称用脱敏错误码退出，退出码为 2。先用短事务记下模型调用编号，放开数据库锁，再等待模型；回来后重新检查租约、账号、授权、原文、上下文和工单版本，过期结果不能落成提议。

真实文字入口使用独立子进程，父进程最多等 20 秒；请求、响应和返回结果有大小上限，只发一次 HTTP 请求。超时、崩溃或租约遗失保留原调用编号，不能自动再花一次钱。编号用于查供应商日志，不代表供应商保证去重。未知事项可以人手处理或忽略，不能靠重新归单偷偷再调用。

新增迁移 **0021_reviewed_product**，记录模型提交标记与建议消费结果；接在 0020 后，不改写共享旧迁移。消费记录随来源／账号／工单删除有明确外键处理。

## 界面、语言和不闪烁

用珍珠白卡片、雾蓝主色和少量玻璃导航替代绿色。登录和工作台都有中文／English／粵語按钮。只保存语言偏好；不把聊天送给翻译服务。界面词典翻译，客户原文、工单内容和批准正文保持原样。切换时不重建组件、不清空表单或登录。

每次读取仍经过后端身份与归属检查。登录期间内存保留旧画面，ETag 比较有没有变化，没变用原数据；只替换变了的部分。304 必须匹配本地已保存答案才能使用。操作、失去权限、退出和换账号会清理相关缓存。不增加离线业务授权、不缓存 QR、不增加聊天离线 service worker；也没有声称数据库不用读。开发时改源码导致 Vite 整页重载，与成品每几秒检查状态是两回事。
