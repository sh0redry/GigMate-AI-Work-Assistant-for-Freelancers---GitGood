# 协作检查表

## 任务开始前

- [ ] Issue 写明场景、模块、依赖、范围、排除事项和验收 case_id。
- [ ] 已读相关 ADR、契约及业务状态规则。
- [ ] 涉及公共字段或状态变更，先形成契约修改与影响清单。
- [ ] 分支为 feat/fix/docs/chore；批次覆盖已授权里程碑内尽可能多的相关任务，仍保持可审查。
- [ ] 批次同时规划实现、迁移、契约、正常/失败测试和中英文文档；完成后统一验收，不逐个小任务要求用户验收。详见[A 的开发演进](role-a-development-roadmap.md)。
- [ ] 测试输入为虚构或有独立授权的数据，未把真实聊天写入公开任务。

## 开发与提交前

- [ ] 开发中自行检查和修复；外部依赖阻塞时完成不受阻工作，明确未验证项；统一验收不替代独立评审或扩大授权范围。
- [ ] 模块通过应用服务协作，未绕过审批执行或跨模块随意写表。
- [ ] 账号归属、来源、版本、幂等和异常路径已考虑。
- [ ] 受影响英文说明、中文检查和契约样例在同一变更中同步。
- [ ] 无密钥、session、QR、真实原文和含敏感内容的截图。
- [ ] 当前基线执行 check_baseline；应用阶段执行对应实际检查。
- [ ] 实际检查输出已保存到 PR 描述，未把未执行测试写成通过。
- [ ] 新迁移与锁文件完整；未修改已共享迁移。

## PR 审查

- [ ] 说明触发条件、修改后行为和已知限制，链接 Issue 与 case_id。
- [ ] 共享 schema 改动有版本和迁移说明；正反样例已更新。
- [ ] 新需求不会使“提议”等同“确认”，或使 AI 直接执行外部写入。
- [ ] 过期批准、跨账号访问、重复事件、结果未知有对应验证。
- [ ] 文档没有错误描述当前功能状态，启动命令均真实验证。

## 单人阶段与多人阶段

当前你是唯一维护者：使用 PR 记录自查，明确填写 solo self-review，检查通过后可自行合并；不设置需要不存在审核人的流程。涉及架构/契约变化仍需 ADR 和影响记录。

其他成员加入后：代码 PR 至少一位独立审核人；共享 schema、迁移和审批规则由受影响模块负责人复核。分支保护与 required checks 在 GitHub 中另行配置，仓库文件不能自动开启这些设置。

## 合并与交接

- [ ] main 可检查且文档状态正确；应用阶段 main 可运行。
- [ ] 迁移和配置变更有说明，未合并会破坏环境的半成品。
- [ ] Issue 更新完成证据，阻塞和后续事项有独立任务。
- [ ] 模块负责人未指定时注明由仓库维护者负责，不虚构团队成员。
- [ ] 新成员能按入口复现验证；应用阶段另做 clean-checkout 启动测试。
