# 客户会话工作区：第一批

2026-10-18 · A 板块 · [English](../en/customer-conversations.md)。

本批新增前端工作区，复用当前安装的同源 API，不创建另一份 WhatsApp 会话、不种数据库、不改变白名单或开启模型。原连接页、工单处理路径和发送面板继续保留。

## 启动与使用

使用自己已有的 WAHA 安装和工作台账号。在 `apps/web` 的 PowerShell 中执行：

```powershell
$env:GIGMATE_REAL_API_URL = 'http://127.0.0.1:18702'
npm run dev
```

打开终端打印的根地址（通常 http://127.0.0.1:5173），登录后选择 **客户会话**。成品页只连接一个后端，没有环境切换。未绑定连接的演示库在此仍为空；启动前端不升级旧后端。本批不迁移或重建用户原有真实安装。

1. 选择安装连接和已授权聊天，可搜索及筛选个人／群聊。列表每页 8 个会话，约每 15 秒检查当前列表页的预览。新消息标记只是本次会话内 GigMate 的观察，不是 WhatsApp 未读数，也不会自动发送已读回执。
2. 当前聊天可见时约每 3 秒读取最新 50 条；可加载较早分页，每次窗口最多 10 页／500 行。刷新重读已显示窗口，更新编辑、撤回及送达状态；分页移动时在上限内追到原有锚点。这是**复用现有时间线 API 的有界轮询，不是新增服务端增量／推送接口，也不保证完整历史**。浏览器后台标签页停止轮询。权限拒绝清理内容、文字草稿和当前选择；临时网络／状态失败保留仍允许读取的旧内容和输入，但关闭发送。
3. 看旧消息时，新消息不抢滚动位置，可点击新消息按钮跳到底部；加载更早记录保留阅读位置。历史／快照标识保留，显式历史导入仍在连接设置中。
4. 对话下方准备回复。只在新页面折叠发送授权、来源／类型、引用、固定政策及记录；原面板默认行为不变。文字、附件、语音、视频和其他已有类型继续通过 `WahaSend`。引用传递归属明确的快照 ID。打开聊天不自动发送已读回执、不下载原文件、不触发 OCR／模型。
5. 独立发送授权、保存草稿、准确正文的最终核对／批准、持久网关和未知结果核对继续生效。未知发送保留原身份，不能用新请求试探是否成功。变更操作进行时阻止导航／换聊天。按连接／聊天在组件内存保留未发送文字及手动／辅助来源，从工单返回仍保留；刷新／退出后丢弃。换聊天后附件及引用选择需重新核对。原网关仅使用既有恢复机制，不新增正文浏览器持久缓存。
6. 侧栏明确选择本次关联工单，一个聊天可有多单。点击字段来源定位准确消息修订；修改／撤回显示失效提示，不当作当前客户确认。更早来源在相同窗口上限内查找；未找到时到工单核对或明确导入历史。打开工单保留返回会话入口，工单字段和变更也新增“在客户会话中查看原话”。
7. 选择当前、收到的、带完整修订证据的客户文字，进入“从所选消息核对新建工单”。原建单页带入会话和来源提示，仍重新读取当前原文、逐项选择关键字段依据并明确确认，不自动建单／确认。编辑／撤回会清除旧来源勾选，不悄悄升级成新修订。没有新增任意消息直接归入已有工单的命令，继续使用既有业务复核／归单流程。
8. 附件按钮复用原媒体预览／处理／复核组件。实际能力仍取决于后端、原文件／来源检查、授权、模态和供应商配置。本前端不启用语音转文字。

## AI：已有实现与待接协议

侧栏读取已有 `GET /work-orders/{id}/drafts`，只提供未过期、`proposed`、含 proposal ID、归属准确工单／会话、工单版本一致且 `execution_authority: false` 的建议。当前绑定最终由后端检查，不把存储的商户手写文字冒充新生成 AI 结果。

商户核对全文并明确允许替换输入后，单次调用 `POST /drafts/{id}/consume`，核对返回身份、文字、提议和上下文／工单绑定，再以 `agent_assisted` 放入共享编辑器。采用不会创建发送动作、批准或外发。新消息变化使本地建议核对失效，需明确刷新。采用结果未知不自动再次消费。旧后端返回 404 时说明需要升级草稿能力，保留工单详情及手动聊天回复。

**本批未实现：**根据当前聊天重新生成回复、真正模型润色、自动触发或自由 Agent。B 现有草稿接口主要存手写文字或复用已有提议，不能改名就宣称支持新生成。这是前端及交接成果，不等于真实模型效果已验收。

### 与 B/C 的新回复生成协议（仅设计目标）

新增端点前先约定独立版本并从源模型生成契约。请求需有归属明确的会话、有工单时明确选定本次工单、准确来源修订、预期上下文／工单版本、回复／润色意图、商户输入及持久请求身份。新客户可能尚无工单；多单歧义需选择，不能默认第一单。不能向现有仅支持工单草稿的命令塞入未声明字段。

B 负责真实模型、有界上下文、提示注入、价格／token／调用限制、取消／提交和未知费用核对；C 负责业务语义和允许提出什么；A 负责连接身份、媒体读取和最终外发边界；D 可将后续生成契约接入现有侧栏／编辑器。返回必须只是带服务端来源、上下文／工单绑定、过期和 `execution_authority: false` 的提议。采用不授予发送权限；未知请求保留原身份，不盲目再次付费。本设计不声称新增了对应端点或生成 schema。

## 兼容与证据

未修改后端、迁移或公开请求结构。聊天、时间线、映射或发送能力缺失时明确说明，不向产品注入合成替代数据。conversation ID 来自明确选项或收到的时间线记录，绝不与 chat ID 混同。发送面板的新属性和紧凑布局均为可选，原入口保留默认行为。

自动化：前端 **195 passed**，含新增 19 项合成会话/API/DOM 回归；TypeScript、生产构建通过。生成类型漂移、格式、源契约导出、适用 Ruff 和基线证据见进度记录。已有包体积提示仍在。复用的时间线／草稿绑定后端用例为 **51 passed / 2 skipped**，使用临时 SQLite，不证明 PostgreSQL 锁。

浏览器检查使用临时本机合成服务，不连接 WAHA／数据库／模型且不支持发送。真实手机送达、回执时序、模型质量、媒体实际兼容及长时间断线恢复仍需人工验收；代理没有发送真实消息或调用付费模型。

## 统一人工验收

需要升级后端时，先由安装负责人更新，再用自己的真实测试安装验收：

- 确认根地址代理到正确真实安装，使用该安装账号和获同意的测试聊天，核对连接及采样新鲜度。
- 用另一个获同意的测试账号新发文字、编辑、撤回；无需手动刷新即更新，同一消息只一条气泡，不恢复撤回正文。上翻时测试新消息不抢滚动。
- 切换聊天再返回，不串收件人／正文，文字草稿回到正确聊天。未知／待核对发送用原身份恢复，不重发试探成功。
- 手动准备、核对批准并发送文字、附件、引用回复，在手机核对实际内容和收到情况，不把供应商接受当送达。
- 有 B 有效模型提议草稿时，明确采用，先确认未发送，再修改／核对并通过原网关批准发送。旧后端没有草稿接口则记为阻塞，不计通过；新生成／润色不在当前交付内。
- 选择来源进入建单核对；从字段定位原话。编辑已勾选来源后重新选取／核验。验证多工单选择和返回路径。
- 验证撤权／暂停、断网／重连、退出账号、手机和三语，客户原文不翻译。只保留脱敏结果，不提交真实聊天、文件、号码、二维码或密钥。
