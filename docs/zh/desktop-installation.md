# 桌面自动启动版：安装与使用

[英文说明](../en/desktop-installation.md)。这是在你自己电脑运行的 GigMate：桌面程序负责启动 Docker 里的后端、独立消息处理程序、数据库和 WhatsApp 连接。没有团队服务器，也不是离线软件或应用商店上架版。第一次下载环境、使用 WhatsApp 和调用 AI 都需要网络。

## 第一次安装

1. 在 GitHub Releases 下载对应文件：Windows 选 x64 `.exe`；M 系列 Mac 选 `mac-arm64.dmg`／`.zip`；Intel Mac 选 `mac-x64.dmg`／`.zip`。zip 要先解压；DMG 里的 App 先复制到 Applications，再打开。
2. 设置自己的账号与至少 12 位密码。安装包没有测试账号、聊天、API Key 或 WhatsApp 登录状态。
3. 首次配置创建独立的空白工作台。**安装、正常启动、升级和重装都不会删除已有数据库、密钥、聊天或 WhatsApp 会话。** Windows 卸载器保留应用数据；构建编号只记录来源，不再触发清空，旧重装标记也不再生效。不读取或导入源码项目和开发环境数据。
4. 需要 Docker Desktop。GigMate 会检查它、尝试打开已安装的 Docker 并等待就绪。没装时点“安装 Docker”下载官方安装包；首次官方安装、许可、系统权限，以及 Windows 可能要求的 WSL2／重启，需要你完成一次。程序不能替你点击系统安全授权。你不用再安装 Python、Node.js 或自己填 `.env`。
5. 可填自己的 DeepSeek Key，明确勾选启用 AI，并填写核对后的**美元／1,000 输入和输出 tokens 价格**以及每次请求的美元预算（大于 0，最多 10）。这不是人民币／百万 tokens。价格、凭据不完整或无效时关闭 AI，手动工作台仍可启动，不移除后端费用门禁。Key 经系统加密后保存，只放入 API／worker 可读的独立模型卷；monitor 仅取得必要的 WAHA 配置和绑定，不能读取模型卷。业务网页和安装包不含密钥。
6. 点启动。程序在 Docker 内准备 Python 环境、迁移空数据库、建立你的账号和空白聊天授权，然后启动 WhatsApp、后端、消息处理和连接监测。健康检查通过就打开工作台。使用刚设置的账号登录，再扫码并分别授权聊天／发送。

## 以后怎样打开

平时双击会复用系统加密配置和原 Docker 项目，正常退出只停止自己的后台并保留卷。在“启动／连接设置”中留空 Key 表示保留旧凭据；取消 AI 勾选并保存启动可关闭 AI，也可明确选择删除 Key。尚未确认价格的旧配置以 AI 关闭状态启动。保存的回环端口被占用时会改用空闲端口，保存新地址并同步后端可信来源后再打开工作台。桌面浏览器分区独立于开发网页。只允许本机 Unix socket／Windows named pipe，拒绝远程 Docker。

配置损坏或系统钥匙串无法解密时，启动会停止，**不会删除或重新创建数据**。请保留配置、原系统钥匙串和 Docker 卷，联系维护者。重装不能代替恢复／备份；系统保护的密钥不保证能跨电脑迁移，本批没有自动备份或导出功能。

## 可选的旧环境清理

清理独立于启动。在启动页展开“旧环境清理”，先获取清单；当前工作台不会进入清单。默认只列出同时具有桌面归属标签及有效项目标签的旧桌面资源。另行勾选后才列出 `gigmate-waha-a02`、`gigmate-waha-team` 和 `gigmate-waha-recovery` 等旧项目，其中可能包含备份。不把无标签的同名资源作为删除目标。

核对每个容器／卷的名称、ID、项目、创建时间，逐项选择，并输入界面要求的删除文字。清单两分钟后失效、仅可使用一次；执行前再次检查 Docker 是本机及所选资源身份。身份变化或清单外目标会拒绝操作。不做 prune、通配符删除、profile 删除或目录扫描。删除永久生效，Docker 失败时可能部分完成；结果不明应重新读取清单，不会自动重试。需要的资料请先自行备份。

## 客户明明说了地址，AI 却漏掉怎么办

进入工单，点 **“手动补充／修改字段”**，选择地址、时间、业务内容、数量、规格或截止时间，填上正确内容，选择对应客户原文，核对后保存。只有原文确实表示客户明确确认时才勾选“客户明确确认了这个值”；否则仍保留待确认。

保存是你自己的明确决定，不是 AI 自动确认。改时间会同步日历；旧的未发送草稿作废，仍然缺的内容才重新准备询问。拒绝过某份回复也能使用这个入口。来源已撤回／修订、版本过期、不属于你、工单已结束或时间撞期时会拒绝保存；网络中断导致结果不明时保留原请求，核查后再恢复，不盲目重复操作。**改字段本身不会发消息。**

## 这一版的边界

发布流程先将 tag 固定到一个提交，用 PostgreSQL 验证后端／契约，再以只读权限构建三个原生目标。只有独立发布 job 具有写权限；上传前针对实际安装包和 `SOURCE_COMMIT.txt` 生成并校验 `SHA256SUMS.txt`。只上传到已有草稿 Release，拒绝移动后的 tag，不覆盖已有附件。校验和证明文件完整性，不等于代码签名或供应链证明。更新 PR 不会重建或替换已经上传的安装包，需要另建 tag／运行并验收。

桌面 CSP 精确允许受控的 blob 语音和 PDF frame 路径，保留脚本／对象／远程来源限制及原 iframe 沙箱。`python scripts/check_desktop_preview.py --browser <Chromium或Edge路径>` 用本机合成内容核验真实浏览器的 WAV 时长加载、沙箱 blob 导航及 CSP 拦截情况；不证明原生 PDF 阅读器、真实已授权附件展示或手机送达，各平台仍需核验。

这是 GitHub 分发的首版安装包，没有 Apple 开发者签名／公证和 Windows Authenticode 证书，系统可能提示无法识别开发者。只安装你明确要用的团队版本，并通过系统自己的批准流程打开。没有自动更新；Windows ARM、Linux 安装包、离线安装依赖、把 Docker 本身塞进安装包、关闭程序后持续运行均未提供。构建／启动成功和真实手机／真实模型送达是不同验收，请以 Release 实际记录为准。

Docker 官方说明：[Mac](https://docs.docker.com/desktop/setup/install/mac-install/)、[Windows](https://docs.docker.com/desktop/setup/install/windows-install/)。其系统要求和许可独立适用。
