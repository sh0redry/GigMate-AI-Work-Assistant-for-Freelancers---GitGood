# 桌面自动启动版：安装与使用

[英文说明](../en/desktop-installation.md)。这是在你自己电脑运行的 GigMate：桌面程序负责启动 Docker 里的后端、独立消息处理程序、数据库和 WhatsApp 连接。没有团队服务器，也不是离线软件或应用商店上架版。第一次下载环境、使用 WhatsApp 和调用 AI 都需要网络。

## 第一次安装

1. 在 GitHub Releases 下载对应文件：Windows 选 x64 `.exe`；M 系列 Mac 选 `mac-arm64.dmg`／`.zip`；Intel Mac 选 `mac-x64.dmg`／`.zip`。zip 要先解压；DMG 里的 App 先复制到 Applications，再打开。
2. 设置自己的账号与至少 12 位密码。安装包没有测试账号、聊天、API Key 或 WhatsApp 登录状态。
3. 阅读并勾选全新安装提示。程序会删除带 GigMate 桌面归属标签的旧容器／数据卷，以及固定旧项目 `gigmate-waha-a02`、`gigmate-waha-team`、`gigmate-waha-recovery` 和旧的模型密钥卷，并清理本程序自己的运行目录与浏览器分区。**这些运行环境中的聊天、工单、审批、数据库和 WhatsApp 登录会被清掉。** 不会扫描／删除源码项目、项目里的 `.env`、其他 Docker 项目、系统浏览器档案或个人文件；新程序也不会读取和导入它们，因此不会带入开发时的数据。
4. 需要 Docker Desktop。GigMate 会检查它、尝试打开已安装的 Docker 并等待就绪。没装时点“安装 Docker”下载官方安装包；首次官方安装、许可、系统权限，以及 Windows 可能要求的 WSL2／重启，需要你完成一次。程序不能替你点击系统安全授权。你不用再安装 Python、Node.js 或自己填 `.env`。
5. 可填自己的 DeepSeek Key，并明确勾选允许 AI 分析随后授权的聊天及承担费用。暂不填则 AI 关闭，仍能手动处理业务。Key 用系统钥匙串／系统加密能力保护，只交给本机私密后端配置，不交给业务网页，也不会上传到 GitHub。
6. 点启动。程序在 Docker 内准备 Python 环境、迁移空数据库、建立你的账号和空白聊天授权，然后启动 WhatsApp、后端、消息处理和连接监测。健康检查通过就打开工作台。使用刚设置的账号登录，再扫码并分别授权聊天／发送。

## 以后怎样打开

平时双击 GigMate，它会沿用你自己的数据并自动启动服务，**不会每次清空**。正常退出会停止这套后台，保留数据。可从 GigMate 菜单重新打开“启动／连接设置”配置 Key。重新安装或换另一份构建会再次显示全新配置核对；Windows 安装器会明确留下下次重置标记。只有你在首次配置页明确同意后才清理，不会在打包／构建镜像时动数据。桌面窗口有独立浏览器分区，不沿用开发网页 `127.0.0.1:18780` 的登录。只允许连接本机 Docker，远程 Docker 会被拒绝。

## 客户明明说了地址，AI 却漏掉怎么办

进入工单，点 **“手动补充／修改字段”**，选择地址、时间、业务内容、数量、规格或截止时间，填上正确内容，选择对应客户原文，核对后保存。只有原文确实表示客户明确确认时才勾选“客户明确确认了这个值”；否则仍保留待确认。

保存是你自己的明确决定，不是 AI 自动确认。改时间会同步日历；旧的未发送草稿作废，仍然缺的内容才重新准备询问。拒绝过某份回复也能使用这个入口。来源已撤回／修订、版本过期、不属于你、工单已结束或时间撞期时会拒绝保存；网络中断导致结果不明时保留原请求，核查后再恢复，不盲目重复操作。**改字段本身不会发消息。**

## 这一版的边界

这是 GitHub 分发的首版安装包，没有 Apple 开发者签名／公证和 Windows Authenticode 证书，系统可能提示无法识别开发者。只安装你明确要用的团队版本，并通过系统自己的批准流程打开。没有自动更新；Windows ARM、Linux 安装包、离线安装依赖、把 Docker 本身塞进安装包、关闭程序后持续运行均未提供。构建／启动成功和真实手机／真实模型送达是不同验收，请以 Release 实际记录为准。

Docker 官方说明：[Mac](https://docs.docker.com/desktop/setup/install/mac-install/)、[Windows](https://docs.docker.com/desktop/setup/install/windows-install/)。其系统要求和许可独立适用。
