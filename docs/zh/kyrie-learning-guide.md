# Kyrie 的 GigMate 学习手册：从零开始

更新：2026-10-18。[English](../en/kyrie-learning-guide.md)。先会使用[当前前端](role-d-frontend-user-guide.md)，再读代码；不需要一次学完所有术语。

## 把整个项目想成一家小店

2026-10-18 补充：**代码更新了，不代表正在运行的程序也更新了**。
像店里拿到了新操作手册，但后台仍按旧手册工作，网页就会找不到接口。
现在 `scripts/start_product.py` 会一起构建网页、后端和 worker，
还会核对后端接口，确认一致后才提示可以使用。你只打开 18780 这个入口。

“测试用的虚构业务”和项目里的 `.venv` 也不是一件事：前者是一套装假工单的
演示程序，现在用户启动不再运行它；`.venv` 是 Python 工具用的依赖文件夹，
不装假客户、假聊天或假工单，运行启动工具仍需要它。自动测试可以使用虚构消息
检查错误，但不会作为用户可登录的另一个网站交付。

**D 前端**是柜台：展示资料、让你填表和确认。**C 业务后端**是负责记账的办公室：检查这是不是你的工单、能不能改、一起保存日历和待办。**B 模型**是帮忙整理聊天的实习生：能提出建议，但不能替老板确认或直接发消息。**A 连接器**像电话线：接 WhatsApp、保存授权、实际发送。**worker** 是后台做事的人，网页关了也能处理已经存好的任务。

前端能画出按钮，不代表办公室已经支持这件事；API 接口像一个办事窗口。服务端的“能力标记”告诉柜台哪些窗口已交付，账号授权则说明你有没有资格办理。两个条件都要满足。

## “手动”“AI 辅助”“自动”不是一回事

手动建单：你读聊天，填摘要、时间、地址，再确认。AI 辅助：实习生先整理一份建议，你读原文、修改并明确确认。自动：实习生不问你就写正式账本——本项目不允许 AI 这样做。

新单建议只预填摘要，时间和地址仍由你核对后填写。未知值就留空。“客户提议”“客户确认”“商户批准”像三个人分别签字，不能拿一个人的签字代替另一个。

## 你会经常碰到的词

| 词 | 通俗理解 | 为什么需要 |
| --- | --- | --- |
| React 组件 | 一个负责画某块页面的函数 | 把登录、日历等分开，方便维护 |
| TypeScript 类型 | 表格的填表说明 | 提前发现把数字、日期、编号传错 |
| API 请求／响应 | 交表格／办公室答复 | 前端不自己决定业务已经保存 |
| 数据库事务 | 一套手续一起办完，失败一起撤回 | 工单改了但日历没改会出事 |
| 来源修订 revision | 客户原消息的第几版 | 客户编辑后，旧地址不能继续当依据 |
| 版本 version | 这份工单更新了第几次 | 防止你按旧页面覆盖队友的新修改 |
| 上下文 context | 对话目前更新到哪一轮 | 新消息来了，旧批准可能不再适用 |
| 幂等键 | 这次操作的小票编号 | 断网后拿同一小票查，不重新点一份 |
| 回执 receipt | 系统留下的办理结果 | “没收到答复”不等于“没办成” |
| 租约 lease | 后台任务暂时交给某个 worker 的凭条 | 防止两个后台人员同时认领 |
| 数据库锁 | 办公室暂时占用这份档案 | 检查和保存之间避免被同时改动 |
| migration 迁移 | 给已有账本加一栏的升级步骤 | 升级数据结构，保留旧资料 |
| commit | 一次有说明的本地存档 | 可以回看哪一步改变了什么 |
| PR | 把存档送给队友审查的申请 | 提交 PR 不等于合并，更不等于已部署 |

不要把“聊天编号”和“业务会话编号”当同一种编号。它们像电话号码和客户档案号，必须通过办公室的对应表联系，不能因为长得像就混用。

## 为什么这次不再整页闪

以前像每几秒把整页笔记擦掉重抄。现在留着笔记，先问办公室“变了吗？” **ETag** 是答案的指纹；**304** 表示没变，继续用旧答案；**200** 带来新答案。每次仍检查权限、仍读取数据库，所以主要减少传输和画面替换，不是完全不读数据库。

**缓存**就是本次登录内存中的笔记；换账号或退出就清理。断网时可以标明“上次读取”，但不能拿旧笔记当保存许可。`stableShare` 像只替换变了的便利贴，不撕掉整本笔记。

## 为什么模型不能一直占着锁

不能一边等实习生查资料，一边锁住办公室的账本。现在先记下这次模型调用编号，释放锁，等答复，再重新检查资料有没有变化。实习生迟到了，或客户改口了，就不能用旧答案写入。

20 秒期限像闹钟，超时会结束本地模型子进程。但结束等待不代表供应商没有收到请求，也不代表不会收费，所以保留原编号、不能自动再调用一次。测试用的是本机假供应商；不等于真实模型准确率已证明。

## 语言和外观从哪里来

`i18n.ts` 管理当前语言；`locales.ts` 是界面用词的中／英／粤词典。它们只换柜台上的标签，不翻译客户原文，不改批准正文。语言偏好可保存，但聊天不送去翻译网站。

`style.css` 的 `--accent`、`--ink` 等变量像共用颜料盒。玻璃模糊只用在导航，正文用清楚的白底。浏览器不支持时用实色；减少动画／透明度的偏好也要尊重。换皮肤不会增加权限。

## 按这个顺序读文件

1. `apps/web/src/App.tsx`：登录、菜单、语言、切页。先找页面名字，不必逐行读懂。
2. `WorkOrderWorkspace.tsx`、`OrderCreation.tsx`：看一条信息怎样显示、怎样让商户确认。
3. `workspace-api.ts`、`order-command-api.ts`：看请求怎么发、小票怎么保留；不要把接口类型当作已经保存。
4. `BusinessLoopWorkspace.tsx`、`ProductTools.tsx`：看需求、排期、待办、查询。
5. `apps/backend/src/gigmate/contracts.py`：双方共用的填表规则；生成文件不用手改。
6. `workorders.py`、`product_commands.py`：办公室检查和保存。
7. `worker.py`、`extraction/reviewed.py`：后台任务与可选模型。密钥只留后端，不放前端。

完整位置见[文件地图](kyrie-file-atlas.md)。开发命令见[开发入门](../en/getting-started.md)。

## 每次练十五分钟

第一天只追踪“点击新建工单→核对→请求→后端→保存结果”。第二天看客户改了原文为什么旧批准不能用。第三天断开临时测试服务，看旧画面保留、写入被保护；恢复后拿原编号核对。第四天切语言，确认输入没有丢、客户原文没变。

只在自己的临时测试环境练习，不用真实聊天、密钥、QR 或手机会话做学习截图。当前代码交付和仍需队友验收的部分，以[交付说明](bcd-product-delivery.md)为准。
