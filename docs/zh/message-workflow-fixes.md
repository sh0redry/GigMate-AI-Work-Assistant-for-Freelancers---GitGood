# 消息理解与新手流程修复范围

对应 [英文架构决定](../en/adr/0009-message-routing-and-review-recovery.md)。本批不绕过人工确认，不自动发送，不重新启用虚构业务环境。

| 需求 | 实现与边界 |
| --- | --- |
| 中文模式夹杂英文、AI 字段格式不兼容 | 新提示词要求中文说明并给出精确字段示例；来源和整体安全校验之后逐字段验证。错误字段留空，保留有效摘要和字段。原始客户英文、品牌名称、手工标题和历史记录保留原文。 |
| 同一客户多个事项拆单 | 给模型各张开放工单的摘要、字段和版本，允许判断另一项新业务；多候选时按选中工单自己的版本核对。每条消息有独立任务。 |
| 识别失败不连锁 | 不把旧失败当成下一条的拒绝条件；普通消息到来导致版本前进时，尚未调用的任务可在最新快照分别分析。撤权期间的任务、被编辑或撤回的旧修订不自动重新调用。 |
| 部分成功即可继续 | 可用新需求进入建单建议；没有结束时间不编造时长，不挡住已识别地址或业务。仍由商户明确创建，不自动确认。 |
| 会话名称 | 后台返回归属已核实的电话号码或名称，迁移 0024 保存名称，避免十分钟候选失效后群名消失。内部身份无法反推出号码时，显示已知名称或明确的未提供号码提示。 |
| 来源时间与分离 | 来源带香港时间并按实际时刻排序；工单只读取明确引用／归入它的消息。人工复核把触发消息与其他聊天背景分开展示。 |
| 动态字段与取消草稿 | 未涉及的规格、数量、截止时间不列为必填；时间和地址仍是当前预约契约的关键项。草稿可拒绝／取消，不能把已发送消息当作撤回成功。 |
| 授权后旧提议失效 | 继续禁止直接确认。重新分析必须明确同意，检查当前来源和版本后排队；同一原文／版本／修订只排一次。未知模型结果先核查，不能盲目重试。 |
| 内部信息隔离 | 移除用户界面里的团队进度、验收和 GitHub 入口；业务接口只提供认证后声明的产品字段，不新增内部进度数据。编号保留在接口内用于归属核对。 |
| 新手教程 | 首次在本浏览器登录显示五步教程，完成／跳过状态仅保存在本浏览器，可随时重开；不替用户操作业务。 |

## 不能假装已实现的部分

- 单条消息同时提出数项独立业务时，现有契约一次只承载一份新单建议。本批没有把它硬改成假的多建议数组；可以由商户从同一原文逐项手动建单，并明确这是另一件事。不同消息中的不同需求则分别分析。
- 电话号码必须由 WhatsApp 接入提供；不能从不透明身份编号猜出真实号码。群聊通常没有一个可当作联系人号码的标识，使用群名。
- 不会保证每句自然语言都识别正确。没有有效业务内容、归属仍含糊、来源安全校验失败、调用结果未知的消息仍需人工处理。
- 历史英文业务标题或旧草稿不会被静默改写，避免改变已经核对过的事实／发送正文。新提议按中文规则生成；既有回复修改后必须重新审批。
- 原来的桌面打包暂停要求继续有效；本批不发布安装包。
