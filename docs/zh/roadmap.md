# 启动任务与后续阶段

当前只有一位维护者，任务按依赖推进，暂不分配虚构角色。日期和工期为计划，不是保证；比赛材料要求另以主办方通知确认。

| ID | 阶段与任务 | 依赖 | 完成证据 |
| --- | --- | --- | --- |
| BASE-01 | 英文介绍与中文检查入口 | 无 | 链接有效，根 README 不引用中文 |
| BASE-02 | 范围、模块、业务规则与 ADR | BASE-01 | 规则一致且状态清楚 |
| BASE-03 | schema、API 约定、样例与校验 | BASE-02 | 正反例及引用检查通过 |
| BASE-04 | 任务/PR 模板及代理规则 | BASE-02 | 单人/多人流程明确 |
| SKEL-01 | 锁定运行时依赖、开发配置 | BASE-03 | 锁文件、真实命令、配置模板 |
| SKEL-02 | 数据库、迁移、认证和账号隔离 | SKEL-01 | clean checkout 迁移与权限测试 |
| SKEL-03 | 持久消息/任务、回放和抽取桩 | SKEL-02 | 去重、重启恢复及共同样例 |

第一步全部内容指 BASE-01 至 BASE-04 的文档与契约基线。本阶段结束后立即开始可运行骨架；LIVE-01 可独立验证，但本阶段不把尚未实测的接入写成成功。

单人建议先为每个后续任务创建 Issue；记录阻塞，不必提前拆成五个并行项目。成员加入后按实际能力分配模块，先阅读入口和共同样例，再领取具体验收任务。P1/P2 在 P0 通过后推进。
