# WAHA 消息同步与媒体元数据：整批交付和验收

2026-10-09 · **Andy_WAHA_message_sync** · 从 **ebf9398**（PR #11 当前成果）创建。[English](../en/role-a-message-sync-acceptance.md)，[实现决策 ADR 0005](../en/adr/0005-bounded-waha-observations.md)。

## 已交付什么

| 能力 | 本批实际行为 |
| --- | --- |
| 聊天管理 | 每次发现最多 100 项、offset 最多 10000；后续页保留已发现选项直到过期。页面搜索/个人/群聊/已授权筛选作用于已载入列表，后续聊天需加载更多。仍须明确保存授权，最多 100 个。 |
| 消息时间线 | 仅自己当前授权的聊天，按时间和稳定标识分页；实时修订/撤回优先，展示来源时间、方向、处理和送达状态，不给前端原始 provider ID。 |
| 有范围的历史导入 | 每次再次明确同意，选择 1–20 个当前授权聊天、过去 30 天内固定区间、1–1000 条扫描上限。页面提供近 1/3/7/14 天选项；保存快照，修订为 null，不伪造原消息/编辑过程。 |
| 持久同步任务 | 每连接一个活动同步；页游标和进度原子落库，120 秒租约，旧持有者不能提交。每页连续读取失败最多三次并退避；重启只重试只读查询。取消持久化，失败后可明确重查原范围。 |
| 缺口补查 | 选择已恢复故障的非空时间区间和聊天，受控补查；不自动清除故障，也不保证全部恢复。 |
| 缺失来源查询 | 已验签且当前授权的未解析编辑/撤回/ACK 仅保存范围内的目标/方向元数据。明确查询可能找到当前快照，不虚构之前的修订、不让原未解析事件直接变成业务变更。 |
| 群聊与引用 | 区分个人/群聊；供应商给出的参与者映射为稳定的应用 UUID。只链接该聊天内已知消息，不复制引用正文或向页面暴露原参与者 ID。参与者不是账户归属或业务批准。 |
| 媒体基础 | 识别图片/音频/文件/视频/其他，保留可选说明文字、声明 MIME/文件名、编辑/撤回观察和支持的 ACK。排除下载地址、原始引擎字段和二进制；说明文字更新保留已知附件信息，短标识仅匹配该聊天/方向的已登记身份，歧义拒绝。 |
| 本地准备 | 可选 remember-database 验证旧安装 binding 后，原子保存绑定工作区的私有本地 DB 地址，后续 wrapper 无需每次重设环境变量。团队 profile 继续管理自己的 DB。 |

**媒体范围已按你的答复确定：只做元数据与说明文字。** 不下载/展示原文件，不做语音转文字、OCR，不把文件送给 GenAI。MIME/文件名只是供应商声明，不是已验证的文件内容。原 Compose 关闭事件/API 媒体下载，历史和来源查询都显式 downloadMedia=false。文件读取方式、存储/费用及 GenAI 用途后续商议；本批不做 Cloud API、外发或多 session 配置。

## 权限与组员接口

每次查询/写入前确认登录、安装/账号/聊天归属；网络返回后再次确认账号有效、接收启用、control_version 未变。暂停/撤权会取消任务并记录排除区间；恢复后也跳过这些已记录区间。升级前未记录的授权变化不重建，不声称掌握全部过去拒绝时段。

实时文字继续走原 0.1 标准事件/修订/worker 链路。媒体元数据采用独立持久观察回执，acceptance_kind=observation，不建立标准 Inbox/Job；普通文字/状态/ACK 回执仍是 normalized_event。accepted 包含两类，业务 pending/timed jobs 不含同步和纯媒体观察，组员不能把所有接收成功都理解为提取任务。

历史快照/媒体观察不会自动进入当前提取、批准或发送链路。时间线 id 是稳定展示标识；只有 evidence=revision 时，source_message_id 和 revision 才对应真实标准修订。快照的这两项为 null，不能拿它冒充 SourceRef 来确认关键字段。B 可据此设计有界历史背景上下文；把观察证据升级为来源明确的提案，需要另行处理契约和权限。C 的批准/来源/上下文检查保留；媒体变化推进上下文并让旧提案过期，ACK 不推进。

历史不覆盖实时证据或重新显示撤回正文。同身份重复观察去重；新历史查询可刷新旧历史快照，但不假装还原编辑过程，旧查询不能回退新证据。30 天清理按来源时间擦除快照文字/文件名/参与者/引用元数据，并清理旧同步终态任务、观察回执和来源缺口元数据，身份保留。完整账户/备份删除仍待做。

## 接口与迁移

统一前缀 `/api/v1/connectors/{connection_id}`；资源按账号隔离，变更需登录/CSRF，提交成功后才响应。

| 路径 | 行为 |
| --- | --- |
| POST /operations | 原控制请求新增发现 offset/limit；结果含 next_offset，原默认简短请求兼容。 |
| POST /sync-jobs | WahaSyncCommand + 稳定 Idempotency-Key；当前版本、聊天 UUID、区间、上限、明确同意及可选故障/来源 UUID；202 只是任务已排队。 |
| GET /sync-jobs、/{id} | 状态、计数、覆盖程度及范围，不返回 provider 地址/ID/正文。 |
| POST /sync-jobs/{id}/cancel | WahaVersionCommand，取消后旧租约持有者不能落库。 |
| GET /chats/{chat_id}/timeline | 时间线每页 1–100；不透明游标绑定连接/聊天/时间/标识。 |
| GET /source-gaps | 当前授权聊天的来源缺口，只给安全元数据，不给原目标或正文。 |

新增 **0008_waha_message_sync**，接在 0007 后，新增分页参数及快照/回执/排除区间/来源缺口/同步任务表；不重写原迁移。契约/OpenAPI/前端类型从源模型生成。

每页最多 50 条、每任务最多 100 页。即使供应商给出部分页，offset 也按请求页大小推进，空页结束该聊天。界面分别显示进行中、读完当前可获取记录、达到上限、仍不完整。**complete_history 始终 false**；空页不证明 WhatsApp 全部历史可用。查询期间数据变化可能移动 offset，能去重但不能保证完整性。本实现是本机单安装能力，不是生产吞吐/并发承诺。

## 升级和一次性人工验收

保留私有配置、数据库和登录卷。团队安装执行 `python scripts/waha_team.py up` 后 doctor；旧安装沿用[此前验收文档](role-a-integration-acceptance.md)中的 DB/内部端口/私有 Compose 环境，先迁移 head/check，再重建 ingress/worker/monitor，最后打开新页面。不要为了升级额外 provision，避免覆盖页面授权。本操作者仍使用 DB 16433。旧终端已设置正确 DATABASE_URL 时，可明确运行 remember-database；忽略的 database.json 包含凭据，只保留本机，不复制给组员。它不会启动 DB 或自动认领其他工作区。

打开真实工作台（通常 127.0.0.1:5173，GIGMATE_API_URL 指向 ingress18702），每位组员仍用自己的同意测试账号/聊天，一次完成：

1. 聊天发现/加载更多、搜索/个人/群聊/已授权筛选；保存测试聊天，确认后续页不丢已选项。
2. 在“消息时间线与同步”选择已授权聊天并载入，手机新发/编辑/撤回文字后重新载入，检查修订和撤回标记；原 checkpoint/verify 继续用于文字 1/2/3 序列。
3. 明确同意历史读取，先选小范围/上限，观察进度、刷新时间线，区分历史快照和实时修订。重复同范围不增加重复消息/业务效果；取消活动任务，失败后明确重查原范围。
4. 在较长查询期间暂停或撤销授权，确认任务取消/结果抑制及后续消息拒绝；明确恢复后，新查询跳过已记录拒绝区间。查询期间重启 worker，验证进度/游标继续且不重复。
5. 同意的测试群里发文字并引用已知消息，核对参与者稳定区分和同聊天引用；成员身份不等于业务批准。
6. 发带说明文字的图片、语音/音频和文件，检查类型、说明、文件名或未知字段；没有附件链接/下载/GenAI 调用。编辑或撤回适用的媒体说明/消息，核对元数据/撤回和支持的送达状态，不要求新增业务提取任务。
7. 有来源缺口时明确查询快照，确认修订仍未知、故障未自动清除；有已恢复中断时补查其范围，自己核对残余缺口后再审阅。不为了截图故意注销/断网。

自动检查使用合成资料；真实账号历史/群聊/媒体格式和 Apple Silicon 配对仍需真机验证。E 独立检查权限、归属、并发租约、offset 移动、未知来源和隐私；报告仅记录版本、安全计数和结果，不附真实文字、聊天 ID、二维码、凭据或文件。实际检查结果见[完成记录](progress.md)。
