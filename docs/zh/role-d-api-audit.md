A 负责连接、聊天授权、历史同步、附件、独立发送；C 负责工单、变更、日历、待办、审批。B/E 目前通过后台任务和模型约定参与，没有可随便加按钮调用的独立业务接口。已有字段定义不代表功能已经做好。

本次补齐同步任务详情、附件详情读取，纠正使用说明里“建单未交付”的旧说法。服务器未提供的建单、状态操作和归单按钮不再占着可操作的位置；功能说明仍能查看进度。健康检查、服务器收消息的回调、开发回放和旧别名不放进产品操作栏。

## PR32 页面已准备，正式开放要等验收

“业务管理”准备了今日概览、工作日/休息/间隔设置、排期风险、资料/承诺/问题、延期跟进、接受/拒绝提议、交付检查、带未完成项确认的结束、归档、人工归单/忽略、修改回复和业务发送。来源和版本必须核对，用户再勾选确认。收件会话、完整正文和发送权限要再次核对。

新增服务器能力 `business_loop_reviewed` 默认关闭；老服务器没这个字段也按关闭处理。前端没有开启开关。必须先交付兼容后端、完成迁移、修复 PR32 跨账号发送关联/取消与暂停后仍写原文的问题，再由其他人完成账号隔离、来源版本、权限撤销、重复请求验收后，由服务器明确开放。人工归单还需要 `manual_assignment`；业务发送还需要 `business_sending` 和独立的发送授权。仅安装原 PR32 不会开启这些页面。

[候选合同快照](../../contracts/business-loop-preview.openapi.json)只记录上述固定提交的 14 条路径和依赖字段，用于生成单独的候选类型；不冒充主线实际接口。`generate:api` 和 `check:api` 分别生成/检查两份类型，不手改生成文件。

保存结果不确定时，按账号保留原内容和编号，刷新不会自动再发。排期设置 PUT 的恢复只读取并核对下一版本完整设置，不盲目重复保存。业务发送关联回执必须通过当前账号的 A 接口读取，并核对会话、工单、正文；取消和对账使用已有 WhatsApp 发送页。
