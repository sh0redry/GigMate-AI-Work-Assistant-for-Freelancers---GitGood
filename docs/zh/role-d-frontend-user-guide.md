## 1 现在有哪些页面

登录前只有账号表单；输入为你配置的 **GigMate** 账号和密码，页面不再预填或展示默认开发密码。它不是 WhatsApp 手机登录。

登录后默认进入 **业务工作台**，导航只有 **业务工作台** 和 **WhatsApp 连接**。移除了“D-01 演示预览”“模拟扫码成功”“模拟断线”和“工单回放”，无须找开关隐藏它们。开发测试仍使用虚构数据，但没有对应的用户操作入口。已经存在的测试数据库记录不会因移除按钮而删除。

大家能够连接 WAHA，是团队提供的进展；本次没有重新测试每个人的手机。连接与会话授权可用，不意味着自动建单、通用模型提取或发消息已完成。新建工单、状态修改、回复审批与消息发送在此分支尚未开放。

## 2 打开正确的环境

自己的 WAHA 后端先按[团队本机指南](role-a-team-local-development.md)准备。前端在 **D 工作目录的 `apps/web`** 启动，使用项目固定 Node 24.15.x/npm 11.12.x：

```bash
npm ci
GIGMATE_API_URL=http://127.0.0.1:18702 npm run dev
```

以上是 macOS/Linux。Windows PowerShell：

```powershell
npm ci
$env:GIGMATE_API_URL = "http://127.0.0.1:18702"
npm run dev
```

打开终端输出的本机网页地址，通常是 http://127.0.0.1:5173/ 。18702 是团队默认 API 端口；实际环境不同则用自己的后端地址。未设置时，开发前端默认连接 18000。一次前端进程只连接一个后端，不会因为选页面就换数据库。

账号由本机配置决定；不知道密码时联系负责配置的队友。开发账号只是当前安装的登录机制，生产账号开通和多用户部署仍需后续工作。不要复制队友的密钥／会话文件，不要往真实数据库种虚构工单。更多后端启动和检查见[开发入口](../en/getting-started.md)。

## 3 连接和管理聊天授权

1. 登录后打开 **WhatsApp 连接**。已有可靠的“已连接”状态时不用再扫码；还需明确保存要处理的聊天授权。
2. 没有连接记录：联系接入负责人检查该账号配置，再点 **刷新连接**。读取失败与没有配置是不同情况。
3. 需要关联时，按页面提供的 **开始连接** 或 **重新连接并获取二维码** 操作；手机 WhatsApp → 关联设备，扫描网页二维码。操作处理中等待结果。图显示出来不代表手机已关联，最后看新鲜的连接状态。
4. 二维码只暂存内存。获取后 30 秒隐藏，可见时约每 20 秒更新；服务可能更早换码。暂停、退出、离开或读取不可靠时隐藏。失败后先刷新状态，不复用旧图。
5. **载入会话与授权** 读取已保存选择。连接正常时点 **发现最近会话** 加载候选；它不是导入完整历史，每批最多 100 个，可明确载入更多。
6. 勾选后点 **保存会话授权** 才生效。搜索／个人聊天／群聊筛选／8、16、24 条分页只浏览已载入列表；其他页的勾选仍保留。**已授权** 筛选看已保存事实，不是尚未保存的勾选。
7. 取消勾选后保存减少授权；**撤销全部授权** 覆盖全部页。已有授权在断线、暂停或接入配置不可用时仍可读取、撤销。**放弃更改** 恢复保存事实。
8. 新候选通常十分钟过期；过期、另一窗口改过授权、读取失败或保存答复丢失时，先重新载入、核对，再操作。新发现可能刷新名称，但上游未提供昵称时不会保证恢复；号码标签会说明“未提供昵称”。
9. **暂停消息接收** 暂停接收；**恢复消息接收** 恢复已有授权，不保证补齐期间遗漏消息。授权用于读取／处理，不开启自动回复，也不直接确认工单。

操作答复丢失时，使用 **使用原请求核对**，保留原参数和请求编号。服务已报告 `result_unknown` 时，用 **核对未知操作（不重发）**；不要另点重连来替代核对。连接状态、消息处理服务和历史完整性分别检查。

故障已恢复后，核对时间范围，明确确认无需补导历史，再用 **清除已恢复故障**。只移除待处理标记，审计保留；未恢复故障不能清除。消息同步区域可以查看允许范围的时间线／同步进度，历史观测和附件信息不等于已整理成工单或解析了附件。

## 4 业务工作台

用 **搜索业务** 和 **工单状态** 找工单。筛选隐藏当前选择时，详情仍保持打开并有提示；不会偷偷切换业务。没有工单可能是正常状态，连接成功不会自动生成一张。页面说明自动／手动建单尚未开放，不提供假数据填充按钮。

详情显示当前版本、时间、地址和字段状态。未知地址仍显示 **未提供**。来源链接指向具体消息和修订；**显示会话** 可查看全部关联会话或一条。来源在其他会话被隐藏时，切回全部查看；某一修订未载入会提示需复核，不拿较新原文代替旧依据。

变更卡区分“谁提出”“顾客是否确认”“商户是否已批准”。目前只开放时间安排确认：点 **核对并确认安排**，比较新旧值、来源和版本，明确勾选，再点 **确认并同步安排**。

冲突、失效、来源缺失／撤回／归属不明、过期数据、已完成／取消工单和未支持字段都不可确认。刷新后提议或版本改变，旧核对失效，需要重新核对；不会把你对旧方案的勾选算成同意新方案。

成功后由后端同步正式工单、内部日历和准备待办，取消旧自动任务并保留历史；**不会给客户发送消息**，也不自动同步手机日历。**个人日历** 显示账号全部安排，标当前／其他工单和暂定／正式；时刻按香港时间，全天日期保留原时区。日期筛选包含跨夜安排。

**当前工单待办** 默认显示待处理和受阻；选 **全部（含历史）** 查看已完成／已取消项，查看截止时间、依赖和来源。**刷新业务数据** 重新读取。读取失败时旧数据明确标为过期，恢复成功前禁止确认；写入结果不确定时先刷新核对，不自动重发。

## 5 退出和常见问题

退出／登录过期清除当前页面账号数据、二维码和请求尝试记录；密码不保留在表单。完整刷新后需要重新登录，已保存授权和业务事实仍由后端保存。没有服务器确认退出的网络失败会提示，不假称已经退出。

| 现象 | 处理 |
| --- | --- |
| 登录不成功 | 核对 GigMate 账号、安装密码、前端所指后端与后端是否运行 |
| 看到旧演示入口 | 核对是不是 main／旧目录开的网页，停旧前端并从正确 D 目录启动 |
| 没有工单 | 核对当前账号；尚未开放建单，不要往真实环境种样例 |
| 显示旧连接／旧业务数据 | 服务恢复后刷新，先核对再操作 |
| 授权版本变化 | 重新载入，比较其他窗口的新状态后再保存 |
| 请求超时或结果未知 | 先核对服务器事实，不重复点击或换新请求编号 |
| 手机仍拒绝扫码 | 保留脱敏实际提示，由接入负责人排查；网页成功显示图不是手机成功证据 |

界面会随窄屏调整布局，可能需要上下滚动。真实手机和 Windows 原生运行仍需独立验收；本轮删除演示界面没有重做扫码或修改真实授权。
