## 选择环境与启动

| 页面 | 用途 | 保存范围 |

一个前端进程连接一个后端。WAHA 团队环境创建开发账号，不种虚构工单。先核对环境，不要往 WAHA 数据库补种回放数据。使用基于最新 main 的工作树；如果后端还没有 PR #11 接口，需要由后端负责人先升级后再联调。

回放使用仓库根目录已有启动方式：

```text
docker compose --env-file .env.example -f infra/compose.yaml up --build -d --wait
```

工作台 http://127.0.0.1:18080/ ，回放 API 18000，数据库宿主机端口 54329。已有数据保留，后端准备见[入门指南](../en/getting-started.md)。不要为前端验收重置其他环境的数据或卷。

前端开发使用 Node 24.15.x/npm 11.12.x。在本工作树 `apps/web` 执行 `npm ci`、`npm run dev`，打开 http://127.0.0.1:5173/ ，默认代理回放 API 18000。纯预览无需 Docker/API；登录和回放需要它们。

自己的 Andy 团队环境已升级并运行后，只设置后端 URL：

macOS/Linux：

```bash
GIGMATE_API_URL=http://127.0.0.1:18702 npm run dev
```

Windows PowerShell：

```powershell
$env:GIGMATE_API_URL = "http://127.0.0.1:18702"
npm run dev
```

遵循[Andy 本机开发指南](role-a-team-local-development.md)，使用自己的私有配置／会话。`GIGMATE_LOCAL_PAIRING` 与 Vite/Python 开发桥已退役；开发及部署前端均使用登录后的 `/api/v1`。provider 凭据、session 名称与原始聊天 ID 留在服务端。Windows 原生前端运行验收仍待完成。

## 登录与退出

开发账号 `merchant`／`demo-only-change-me`，或使用初始化时设置的密码。这与手机 WhatsApp 登录不同。登录后选择连接或回放。退出／过期会清理账号数据与临时二维码；成功退出也清理保存的请求尝试信息。刷新后需重新登录，后端授权／业务状态保留。未确定请求只在本标签页可用的会话存储中保存不透明应用 ID 与操作／版本／请求键，不保存凭据或配对材料。

## WhatsApp 连接与会话授权

1. 登录并进入 **WhatsApp 连接**。没有记录时，由接入负责人预配置安装，再点 **刷新连接**。浏览器不任意创建账号／session，也不要求 provider 凭据。
2. 初次 setup 可用时点 **开始连接**；FAILED/STOPPED 等可恢复会话点 **重新连接并获取二维码**。等待操作结果。操作完成不证明手机关联；只有新鲜的 WORKING 采样显示 **WhatsApp 已连接**。活动操作期间不能新建 provider 操作。
3. 等待扫码时自动载入内存二维码，用手机「关联设备」扫码。**刷新二维码** 会替换图片；获取后 30 秒隐藏，页面可见时每 20 秒更新，provider 可能更早轮换。读取失败／状态过期、暂停、退出或离开页面会清理图片。预览不可扫描。
4. 响应丢失时点 **使用原请求核对**，保留原 body／版本／请求键，通过后端幂等核对。`result_unknown` 时点 **核对未知操作（不重发）**，排入只读核对。刷新查看排队／最终结果，不因旧响应丢失另建重连请求。后端拒绝、租约过期及核对结论为准。
5. **载入会话与授权** 读取持久授权及现有有效选项，断线／暂停时也可用。连接后明确点 **发现最近会话**，最多发现 100 个最近会话；其他／旧会话可能不在列表中，这不导入历史。新选项十分钟过期；名称按纯文本显示，应用 UUID 保持不透明。
6. 勾选目标后点 **保存会话授权**。摘要区分未保存与服务端同步，显示已保存数量。保存后读取后端的持久选中 ID。读取授权不会开启自动回复、发送消息或确认工单。**放弃更改** 恢复本次已载入值。
7. 取消勾选已有会话并保存可减少授权，或点 **撤销全部授权**。断线、暂停或 provider 配置不可用时仍可操作，使用最近成功读取的授权版本。版本变化／读取失败／保存响应丢失后，禁用再次保存，需 **重新载入会话**；有未保存勾选时按钮为 **放弃勾选并重新载入**。选项过期后重新载入、发现、核对再授权。写入不自动重试。
8. **暂停消息接收** 不删除 session／选项；**恢复消息接收** 明确恢复已有授权，不承诺导入期间漏掉的消息。版本变化后重读授权。浏览器与 CLI 授权修改需要协调：CLI provision 会按其来源明确替换浏览器保存的白名单。
9. 分别检查 provider 连接、新鲜度、接收授权和处理链路。核对已恢复故障时段后，只有确认无需导入历史消息才勾选确认，点 **清除已恢复故障（数量）**。历史审计保留，不补拉或删除消息；活动故障不能清除。

真实手机关联、独立队友审核、Windows 原生运行仍待验收。见[D 证据](role-d-stage1-acceptance.md)与 [Andy 已实现的 setup API](role-a-setup-api-acceptance.md)。

## D-01 演示预览

进入 **D-01 演示预览** → **模拟扫码成功** → **载入会话与授权**（或 **发现最近会话**）。勾选虚构会话并保存、核对数量；修改／放弃，暂停／恢复，模拟断线后撤销已有授权。暂停／版本变化后和真实模式一样需要重读。离开再进入重置，不建立真实授权，也不请求业务 API。

## 工单回放验收

按首次加载的版本 3 测试。日期是固定的 2026 年样例，以香港时间显示，不随今天改变。已有数据库若已版本 4，重复输入不会产生新一轮提议，刷新不能重置。每次等提议出现再继续；连续不同输入可能使第一条在 worker 处理前失效。

| 步骤 | 点击什么 | 预期看到什么 |
| --- | --- | --- |
| 1 | 登录→工单回放→虚构业务预约 | 业务版本 3、会话版本 4；正式安排 10/07 15:00–16:00，地址未提供；无提议，有原始来源和准备待办 |
| 2 | 另一项已确认预约，再切回主样例 | 正式安排/来源/当前与其他业务标签随选择切换；另一预约为 10/08 15:00–16:00、无待办，回放按钮禁用并说明目标 |
| 3 | 回放：15:00 冲突改期 | 提议 10/08 15:00–16:00、时间冲突、确认按钮禁用；正式安排/日历/待办不变；会话版本 5、2 条消息 |
| 4 | 再点相同输入 | 提示已处理，没有重复创建；仍为 1 张卡、2 条消息，业务版本 3 |
| 5 | 回放：16:30 可用时段 | 新卡 10/08 16:30–17:30、待商户确认；旧卡失效且禁用；正式安排/业务版本 3 不变；会话版本 6、3 条消息 |
| 6 | 点新卡来源编号 | 跳到原文，显示编号、修订号和消息时间 |
| 7 | 16:30 卡的确认并同步安排 | 业务版本 4，正式安排/日历更新，新卡已确认且禁用；旧待办已取消，新待办待处理；地址仍未提供 |
| 8 | 查看新待办 | 新版 main 标题类似「10/08 15:30 准备 16:30 的虚构业务预约」，截止 10/08 15:30。已有旧任务可能保留旧标题，前端不改写它 |
| 9 | 再回放 16:30，切换页面，刷新并登录 | 提示已处理；保持版本 4、2 张卡、3 条消息、2 条待办；状态持久保存，其他页面不沿用旧回放提示 |
| 10 | 退出，试错误密码，再输入正确密码 | 回登录框且不误报请先登录；错误密码中文提示、不能进入；正确密码可登录 |
| 11 | 可选：other / 同一开发密码 | 仅此账号自己的版本 3 工单，没有 merchant 版本 4 数据或另一项预约；回放按钮禁用 |

「个人安排」显示账号全部内部日历，按选中工单标记当前/其他；「待办事项」仅显示选中工单。取消的旧任务保留作历史。窄窗口可能把日历和待办排在下方，需要滚动。

点「刷新回放数据」重新读取。读取失败标明保留的是旧数据，并禁用回放/确认；恢复后读取成功，旧错误与过期标记消失。版本/来源变化需核对当前提议，不自动重试确认。写入结果不确定时，先恢复服务并刷新核对。

## 常见问题与剩余限制

- 列表为空：核对是否误用 WAHA API 18702，打开已加载虚构数据的回放环境。
- 等不到提议：检查回放 API/worker；重复样例不再次生成提议。持续排队需后端负责人核查。
- `WAHA_ENGINE_MISMATCH`：后端无法验证固定 server／engine，需接入负责人核对配置，不绕过校验。PR #11 已支持其验证过的 STOPPED 情况。
- Apple Silicon：PR #11 包含 Andy 的镜像／平台选择；本批前端没有验证实际手机关联，也未升级原有私有安装。
- 手机拒绝关联：保留实际手机提示交由接入负责人核对；二维码显示不证明关联成功。

工单回放仍需调试和独立审核：多会话工单只读取第一条关联对话；多接口刷新不是数据库原子快照；没有 worker 失败/持续排队的完整界面，也没有样例重置、消息编辑/撤回按钮或通用 AI 输入。后端负责最终版本、来源、授权和冲突校验。D-01 产品授权现已实现并通过合成测试；真实 WhatsApp 送达／扫码、自动回复与发送不属于本次已验证结果。Windows 原生联调仍待队友完成。
